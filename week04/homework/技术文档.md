# 雨云讲义测验 Agent 技术文档

## 1. 项目定位

本项目将传统题库管理工具升级为“资料驱动”的 AI 学习测验平台。用户不需要先维护题库，而是上传课程讲义、考研资料或考证材料，由 Agent 收集出卷要求并生成可直接作答的试卷。

首版支持单选题和多选题，完整业务链路为：

```text
资料上传 -> 对象存储 -> 异步解析/OCR -> 文本切片
-> Agent 多轮规划 -> 向量召回 -> AI 生成与后端校验
-> 限时答题 -> 自动保存/交卷 -> 判分/解析 -> 错题重练
```

## 2. 系统架构

```text
Browser
  React + Vite + Ant Design
              |
              | JSON / multipart + HttpOnly Cookie
              v
Go API (Gin)
  |- Session middleware: 匿名会话与数据隔离
  |- Material service: 上传、下载、文本提取、OCR
  |- Agent service: 计划抽取、生成、校验、修复
  |- Exam service: 快照、答题、判分、错题
  `- In-process worker: 解析、出卷、超时交卷
        |                 |                 |
        v                 v                 v
Supabase Storage   PostgreSQL+pgvector   AI Provider
原始讲义文件        业务数据与知识片段     OpenAI 兼容接口
```

前端和后端分离部署。前端只配置 API 地址；数据库、对象存储和模型密钥全部保存在服务端环境变量中。

## 3. 模块划分

### 3.1 前端

| 模块 | 功能 |
| --- | --- |
| 资料库 | 上传资料、查看解析进度、失败原因与章节摘要 |
| AI 出卷 | 选择资料、对话补全计划、确认生成、轮询任务进度 |
| 我的试卷 | 查看生成状态、历次作答、继续答题或重新作答 |
| 答题页 | 左侧答题卡、实时状态、题目标记、倒计时、答案保存 |
| 成绩页 | 总分、逐题正误、用户答案、正确答案、解析和引用 |
| 错题本 | 按原始试卷聚合历史记录，切换最近作答并创建重练卷 |
| 个人主页 | 匿名学习空间的展示信息和本地密码设置 |
| 智能体配置 | 仅服务器本机可更新模型地址、模型名和密钥并测试连接 |

Axios 拦截器统一处理 Cookie、超时、错误提示和全局网络忙碌状态。列表页面使用浏览器缓存先展示旧数据，再静默刷新，以减少云数据库冷连接造成的空白等待。

### 3.2 后端

| 包 | 职责 |
| --- | --- |
| `config` | 环境变量、数据库连接池、迁移和本机模型配置 |
| `controller` | HTTP 协议、会话鉴权、业务编排、任务 Worker |
| `service` | Storage、文档解析、向量化、模型调用与题目校验 |
| `model` | GORM 领域模型 |
| `router` | 路由注册、CORS 和静态入口 |

当前代码将主要业务编排放在 `learning_controller.go` 中，便于作品快速迭代；进一步工程化时可按 material、agent、exam、attempt、job 拆分 Service，并通过接口注入外部 Provider。

## 4. 数据模型

| 表 | 关键字段 | 作用 |
| --- | --- | --- |
| `anonymous_sessions` | `id`, `expires_at` | 30 天匿名浏览器会话 |
| `user_profiles` | `anonymous_session_id`, `name`, `account`, `password_hash` | 当前学习空间展示信息 |
| `materials` | `object_key`, `status`, `text`, `chapter_summary` | 资料元数据与解析结果 |
| `document_chunks` | `material_id`, `ordinal`, `content`, `embedding` | 约 1200 字符的知识片段 |
| `agent_conversations` | `material_ids`, `plan_json`, `status` | 对话上下文与计划快照 |
| `agent_messages` | `conversation_id`, `role`, `content` | 多轮消息记录 |
| `generation_jobs` | `kind`, `status`, `progress`, `retry_count` | 解析/出卷持久化任务 |
| `exams` | `status`, `duration_minutes`, `source_exam_id` | 试卷及错题重练归属 |
| `exam_questions` | `options`, `answer`, `explanation`, `citation` | 生成时的题目快照 |
| `exam_attempts` | `expires_at`, `submit_reason`, `score` | 每次独立作答 |
| `attempt_answers` | `answer`, `is_correct`, `marked` | 自动保存的答案与标记 |
| `wrong_questions` | `attempt_id`, `exam_question_id` | 按作答持久化错题 |

除从属表外，领域主表均通过匿名会话归属；接口查询按会话过滤，从而阻止不同浏览器会话互相读取数据。

## 5. 资料处理

### 5.1 文件存储

后端接收 multipart 文件并限制扩展名和 50 MB 大小。对象 Key 使用：

```text
{session-id}/{unix-nano}.{extension}
```

不把原始中文文件名写入对象 Key，可规避 Storage 对特殊字符和路径编码的兼容问题。Bucket 使用私有权限，service role key 只存在后端。

### 5.2 文本提取

- TXT/Markdown：直接读取 UTF-8 文本。
- DOCX：按 ZIP 读取 `word/document.xml`，解析段落文本。
- 文字 PDF：优先使用 `pdftotext`。
- 扫描 PDF：`pdftoppm` 以 200 DPI 转 PNG，再调用 Tesseract `chi_sim+eng`。
- `pdfinfo` 检查页数并拒绝超过 200 页的文档。

提取结果少于 20 个字符时任务失败，错误原因会回写资料和任务记录。

### 5.3 切片和检索

正文当前按约 1200 个 Unicode 字符切片。每个片段通过 FNV 特征哈希生成 384 维单位向量，写入 pgvector；出卷时对“知识范围”做同样向量化，使用余弦距离召回最多 12 个片段，并将总上下文限制在 12000 字符。

该方案无需额外 Embedding 服务，成本低且结果确定；不足是语义召回能力有限。演进方向是抽象 `EmbeddingProvider`，使用专用中文向量模型并记录模型版本。

## 6. Agent 与生成质量

### 6.1 计划状态机

```text
collecting -> ready -> confirmed
```

Agent 从历史消息中抽取以下必填字段：名称、总题量、时长、难度、单选数、多选数和知识范围。只有数量关系合法且所有字段完整时才能确认生成。

### 6.2 结构化生成

模型必须返回 JSON：

```json
{
  "questions": [
    {
      "type": "single",
      "content": "题干",
      "options": [{ "id": "A", "content": "选项" }],
      "answer": ["A"],
      "explanation": "解析",
      "citation": "讲义中的原文短引"
    }
  ]
}
```

后端不信任模型输出，依次校验：

1. 题量与计划一致，题型只能为 `single` 或 `multiple`。
2. 每题必须恰好 4 个非空且 ID 唯一的选项。
3. 单选恰好 1 个答案，多选 2-3 个答案，且答案 ID 必须存在。
4. 题干、解析和引用不能为空，引用必须能在检索上下文中精确定位。
5. 题干标准化后不可重复。

首次校验失败时，把失败原因加入提示词，允许模型自动修复一次；再次失败则任务进入 `failed`。

## 7. 任务系统

`generation_jobs` 的状态统一为：

```text
queued -> running -> succeeded
                   -> queued (最多重试一次)
                   -> failed
```

上传或确认出卷只创建任务并立即响应。Worker 被通道唤醒，同时每 30 秒扫描队列；领取任务时以 `id + queued` 条件更新，降低重复执行概率。服务启动后将超过 10 分钟的 `running` 任务恢复为 `queued`。

当前 Worker 和 API 在同一进程，适合单实例作品演示。生产环境应拆分 Worker，使用 PostgreSQL `FOR UPDATE SKIP LOCKED` 或消息队列保证多实例并发领取，并为外部调用增加指数退避和死信处理。

## 8. 在线作答与判分

- 开始试卷时后端生成 `started_at` 和 `expires_at`；已有未过期答卷则继续原答卷。
- 答案以 `(attempt_id, exam_question_id)` 唯一键 upsert，刷新后从服务端恢复。
- 单选最多保存 1 项，多选最多 3 项，并验证选项是否合法。
- 用户主动提交与定时任务超时提交最终都进入同一个判分函数。
- 单选和多选都按答案集合完全一致判定；每题等分，成绩为 `正确数 / 总题数 * 100`。
- 题目使用试卷快照，后续重新生成或修改数据不会影响历史答卷。

## 9. 安全设计

### 已实现

- HttpOnly 会话 Cookie；线上可启用 `Secure + SameSite=None`。
- CORS 仅允许配置的前端来源并允许凭证。
- 所有学习数据在服务端按会话过滤。
- 作答 DTO 隐藏正确答案、解析和引用。
- AI Key、数据库连接串和 Storage service role key 仅从服务端环境读取。
- 智能体配置接口只接受 loopback 请求，返回时仅展示掩码密钥。
- 密码使用 bcrypt 哈希，不存明文。

### 边界

当前“个人主页”依附匿名会话，密码只是本地学习空间设置，尚未实现登录、登出、找回密码和跨设备身份绑定。若面向公网用户，应引入 Supabase Auth/OIDC、CSRF 防护、限流、审计日志、恶意文件检测和对象生命周期策略。

## 10. 配置与部署

核心环境变量：

| 变量 | 说明 |
| --- | --- |
| `DATABASE_URL` | PostgreSQL 连接池 URI；为空时回退 SQLite |
| `SUPABASE_URL` | Supabase 项目 URL |
| `SUPABASE_SERVICE_ROLE_KEY` | 仅服务端使用的 Storage 密钥 |
| `SUPABASE_BUCKET` | 私有 Bucket，默认 `materials` |
| `AI_API_KEY` | 模型服务密钥 |
| `AI_BASE_URL` | OpenAI 兼容 API 地址 |
| `AI_MODEL` | 账号实际可用的模型标识 |
| `TESSERACT_PATH` | Tesseract 可执行文件路径 |
| `POPPLER_BIN_PATH` | Poppler `bin` 路径 |
| `AUTO_MIGRATE` | 首次部署建表开关 |
| `COOKIE_SECURE` | HTTPS 部署时设为 `true` |
| `FRONTEND_ORIGIN` | 唯一允许的前端来源 |

后端 Docker 镜像内置 Poppler、Tesseract 和中英文语言包。生产部署建议：前端使用静态托管，API/Worker 使用常驻容器，数据库与 Storage 使用 Supabase，所有密钥通过平台 Secret 注入。

## 12. 可继续演进的方向

1. 将 Controller 中的编排拆分为领域 Service，并为 Storage、LLM、Embedding 定义接口。
2. 使用专用中文 Embedding 模型，增加章节感知切片、混合检索和 rerank。
3. Worker 独立部署，引入可靠抢占、指数退避、任务取消和可观测性。
4. 引入正式账号体系、跨设备同步、RBAC 与教师共享资料。
5. 增加模型调用成本、生成耗时、召回命中率和题目质量评测指标。
